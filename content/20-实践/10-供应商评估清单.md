## 一、这份清单为什么不是 12 问的复制

**〔判断〕** 把 [开工前 12 问](06-开工前12问.md) 原样递给供应商，是这类评审最常见的浪费。原因是**同一个问题问自己和问供应商，好答案与危险信号是反的**：

| | 开工前 12 问 | 本页 |
|---|---|---|
| **问谁** | 问自己的组织 | 问候选方案商 |
| **发生时间** | 立项评审前 | 立项之后、选型阶段 |
| **12 问中的前提组**（Q1–Q4、Q10、Q12） | 必答，答不上来就叫停 | **不要问供应商**。这六问问的是你的组织现状与裁决权，供应商没有资格回答；**供应商主动替你回答，本身就是危险信号**（见 2.1） |
| **12 问中的设计组**（Q5–Q9、Q11） | 答不上来不叫停，转为方案待办 | **必答，且必须交证物**。这是供应商的本职 |
| **危险信号的形态** | 「不知道」「没想过」 | 「当然支持」「完全可以」——**供应商的危险信号是流畅，不是卡顿** |

> **一句话的使用纪律**：**要证物，不要答案。**
> 评审会上听到的每一句「支持」，都应当当场改写成「请演示」或「请提供文档的哪一页」。

## 二、第一道筛：先分清哪六问不该问供应商

### 2.1 六问「供应商替你回答」即危险信号

**〔判断〕** 这六问（12 问的前提组）的答案是**你的组织资产**，不是采购标的。供应商热情地替你回答，意味着他要么在卖一个与你实际约束无关的方案，要么在把你的裁决权收进他的产品里。

| 12 问 | 问的是 | 供应商这样回答 → 危险信号 |
|---|---|---|
| **Q1** 这个系统被允许改变什么 | 你授权的改动范围 | 「我们会帮您梳理出适合 AI 改造的环节」——范围由你的授权决定，不由他的产品能力决定 |
| **Q2** 第一个场景是什么、为什么是它 | 你的痛点与可逆性 | 「我们在同行业有标准场景包，直接上」——**同行业不等于同口径、同权限、同落点系统** |
| **Q3** 哪个旧动作会被取消 | 你的流程减法 | 「不取消任何现有流程，我们是增量部署」——这正是本站的反模式：净增加负担的系统会自然死亡 |
| **Q4** 核心指标的口径谁说了算 | 你的裁决权 | 「我们的平台内置了行业标准指标体系」——**口径裁决权一旦默认交给厂商，本体就不是你的了** |
| **Q10** 出错了谁负责 | 你的责任分配 | 「我们有完整的 SLA 兜底」——SLA 赔的是服务可用性，赔不了一次错误的调价决策 |
| **Q12** 什么情况下叫停 | 你的失败判据 | 「我们的客户还没有失败案例」——见 2.2 |

> **这六问要在见供应商之前自己答完**，并把答案作为**约束条件**写进需求书。
> 顺序是：先用 [开工前 12 问](06-开工前12问.md) 答完前提组 → 再用本页评供应商。颠倒这个顺序，评审会变成听产品介绍。

### 2.2 一个单独拎出来的危险信号：「我们没有失败案例」

**〔判断〕** 这句话在采购语境里不是优势陈述，是信息缺失的证明。理由与本站 [案例](../60-案例/README.md) 页写「一个失败的案例比三个成功的案例更有价值」完全相同：

- 一家真正做过若干个落地项目的供应商，**必然**有叫停的、缩范围的、交付后被弃用的项目；
- 说不出任何一个，通常意味着项目数量太少，或者成功的定义是「验收通过」而不是「仍在使用」。

**可用的追问**：「请讲一个被客户叫停或上线后被弃用的项目，以及你们当时判断错在哪里。」
这个追问的回答质量，经验上比任何成功案例更能区分供应商。

## 三、九条供应商必答项（六问改写 + 三条采购专属）

**〔判断〕** 下表是本页的主体。每一条都给出**要求的证物**——不接受口头答复、PPT 页或「可以定制开发」。

### 3.1 来自 12 问设计组的六条

| # | 问供应商 | 对应 | ✅ 可接受的证物 | 🚩 危险信号 |
|---|---|---|---|---|
| **V1** | 上游系统改一个字段，你的产品怎么发现？**请演示一次字段变更触发阻断。** | Q5 | 数据合同 / 断言配置界面 + 一次真实的阻断日志 | 「有数据质量模块」但演示不出阻断；「会在报表里体现异常」 |
| **V2** | 做回溯评估时，用的是当时能知道的数据吗？**请展示一个带双时间轴的对象。** | Q6 | 对象定义里的有效期区间与事实的双时间轴字段 | 「可以加时间戳字段」——**加字段不等于查询默认按时点口径**；或答「业务上不需要」 |
| **V3** | Agent 用什么身份访问我的数据？无人值守时呢？**请出示权限模型文档。** | Q7（**权重加倍**） | 调用者权限继承 + 工具集白名单 + **无人值守时的岗位委托身份**定义 | 「用服务账号」「可以直连数据库」「权限在提示词里约束」——见 [模块四 4.4b](../10-方法论总结/04-模块四-行动闭环与企业采纳.md) |
| **V4** | 怎么证明它是对的？**请提供评测集的构造方式与一次完整评测报告。** | Q8 | 冻结的金标准集 + 影子运行机制 + 上线判据 | 只有 demo 与客户好评；给出公开基准榜单名次（**榜单名次不能作为证据**，见 [引用与数据来源](../40-参考/04-引用与数据来源.md) 不可引用的数字一节） |
| **V5** | 它上一次说「我不确定」是什么时候？**请展示弃权率指标与转人工路径。** | Q9 | 弃权率看板 + 弃权后的人工接管流程 | 「我们的准确率很高，很少不确定」——**一个从不弃权的系统是一个不知道自己不知道的系统** |
| **V6** | 三周前的某次自动执行，能还原完整依据吗？**请现场查一次历史执行。** | Q11 | 输入、口径版本、模型/提示词版本、触发者、审批人五项齐全 | 「日志里有」——「应该有」等于没有；证据链必须是设计出来的，不是日志的副产品 |

> **为什么 V3 权重加倍**：与 12 问中 Q7 的理由相同——它是唯一一个**答错就必须重做架构**的设计问题。其余五项可以在实施期补，权限模型不能。
> 在采购场景里这一条更重要：自建可以后改，**买来的权限模型你改不了**。

### 3.2 三条采购专属项

承 [自建 vs 采购](09-自建vs采购与退出剧本.md) 2.3 的 S1–S3，补上证物要求：

| # | 问供应商 | ✅ 可接受的证物 | 🚩 危险信号 |
|---|---|---|---|
| **V7**（S1） | 本体定义与证据链能以什么格式导出？**请导出一份给我看。** | 结构化、带 schema、可被第三方系统读取的导出文件；导出动作是产品功能而非服务请求 | 「可以导出报表」——**这不是导出，是打印**；「需要我们协助导出」——意味着退出要看厂商配合 |
| **V8**（S2） | Agent 用什么身份访问我的数据？无人值守时呢？ | 同 **V3**。**采购场景下这一条与 V3 合并评分，不重复计分** | 同 V3 |
| **V9**（S3） | 模型下线或涨价时，我的评测结论还成立吗？ | 书面的模型变更通知机制 + 变更后重跑评测的责任归属（**写进合同，不是写进邮件**） | 「模型是透明可替换的」——透明可替换意味着**行为也会变**，评测必须重跑；见 [模块三](../10-方法论总结/03-模块三-Agentic系统设计与编排.md) 行为漂移一节 |

> **V8 与 V3 是同一个问题**，这里保留编号是为了与 09 页的 S1–S3 对齐。**计分时只算一次**，以免权限问题被重复加权而挤掉其他项。
> 因此实际计分项为 **八条**：V1、V2、V3（权重加倍）、V4、V5、V6、V7、V9。

### 3.3 合规形态：一道先于技术评估的筛子

**〔判断〕** 这一条不进评分表，因为它是**否决项**而不是打分项。

必须在技术评审之前问清：**模型部署形态是什么？数据会不会出企业网络、会不会出境？**
若结论是不可出境而候选方案依赖境外 API，**整个方案不进入评分**，不需要走完后面的流程。
判据与合规路径见 [合规与安全前置](07-合规与安全前置.md) 2.3。

## 四、计分与结论

**〔判断〕** 计分规则与 [开工前 12 问](06-开工前12问.md) 的「前提组/设计组」不同——这里全部是供应商的本职，**没有「不影响开工」的豁免项**。

### 4.1 单项计分

| 该项表现 | 分 |
|---|---|
| 当场交出证物 | 2 |
| 有文档但不能当场演示 | 1 |
| 只有口头答复、PPT 页，或答「可以定制开发」 | 0 |

**V3 的得分乘 2。**满分 **18**（七项常规 × 2 + V3 额外 2）。

### 4.2 结论表

| 情况 | 判断 |
|---|---|
| **V3 得 0 分** | **否决。**与总分无关。权限模型买来之后改不了 |
| **3.3 合规形态不成立** | **否决。**不进入评分 |
| 总分 ≥ 14 且无 0 分项 | 可进入商务阶段；0–1 分项逐条写进合同的验收条件 |
| 总分 8–13 | 可作为候选，但**必须把所有 0 分项转为合同里的交付义务并约定违约责任**，否则不要进入商务 |
| 总分 < 8 | 不要采购。这是一个演示产品，不是一个可被审计的生产系统 |

> **判据不是分数本身，是 0 分项的位置。**一个总分 15 但 V6（证据链）为 0 的方案，比一个总分 11 但处处 1 分的方案更危险——前者意味着产品架构里根本没有这件事。

## 五、反面：这份清单会出错的地方

### 5.1 五种会得高分但不该选的供应商

**〔判断〕** 本清单测的是**可被审计的工程完备度**，它测不出下面五类问题。这是本页最需要被怀疑的地方：

| 类型 | 为什么会得高分 | 真正的问题 | 怎么补测 |
|---|---|---|---|
| **要求你按它的模型重塑业务语义** | 权限、评测、证据链都做得很完整 | 得分项全部满足，但**本体不再是你的**——这是 09 页「买能力、自建语义」判据里最危险的一种锁定 | 问：「我的对象定义和你们的标准模型冲突时，改哪一边？」 |
| **功能齐备但没有真实生产客户** | 产品化程度高，演示能力强 | 所有证物都是功能演示，不是运行证据 | 要求出示**一个运行满一年的客户的运行指标**（弃权率、人工推翻率的变化） |
| **把治理做成了配置项而非默认** | 每一条都「支持」 | 支持不等于默认开启；交付时为了赶进度会被关掉 | 问：「这些约束在默认配置下是开还是关？关掉需要谁审批？」 |
| **交付团队与售前团队不是同一批人** | 售前能答出全部九条 | 评分测的是售前的知识，不是交付的能力 | 要求**交付负责人出席评审并答 V1–V6** |
| **强绑定单一模型供应商** | V9 答得漂亮 | 漂亮的答案可能只是因为他和你一样无法控制上游 | 问：「上一次模型版本变更，你们重跑了哪些评测？报告能看吗？」 |

### 5.2 不要问的四个问题

**〔判断〕** 这些问题在评审会上一定会得到答案，而答案没有区分度——问了只会消耗时间并给人「评审很充分」的错觉：

| 不要问 | 为什么 |
|---|---|
| 「你们的准确率是多少？」 | 没有口径的准确率不可比。该问 V4：评测集怎么构造的 |
| 「支持哪些大模型？」 | 清单长度与你的问题无关。该问 V9：模型变了评测怎么办 |
| 「有多少家客户？」 | 客户数不等于落地深度。该问 2.2：讲一个失败的 |
| 「能不能私有化部署？」 | 几乎所有供应商都会答能。该问 3.3：数据会不会出企业网络、出境 |

### 5.3 本页覆盖不到的

**〔判断〕** 诚实的边界：

- **不含任何具体产品或厂商对照。**理由与 [09 页第四节](09-自建vs采购与退出剧本.md) 相同：市场在快速变化，产品清单半年内就会过时。本页只给判据。
- **不覆盖商务条款**（定价结构、许可模型、服务期限、违约责任的具体写法）。这需要法务与采购，不是本方法论的范围。
- **不覆盖多 Agent 场景**。V6 的证据链判据是按**单 Agent 单次执行**设计的；多 Agent 的审计仍是本站公开承认的未解问题（[模块五](../10-方法论总结/05-模块五-整合视图与展望.md) 未解问题 ⑨）。若候选方案以多 Agent 为卖点，**本清单的 V6 不足以评估它**。
- **分数线（14 / 8）是经验估计，不是实测标定。**它来自八项二值化评分的结构，没有样本支撑。**可以按你的风险偏好整体上移或下移，但不要只移一条。**
- **本页未经真实采购项目验证。**它是从 12 问与 09 页推导出来的，推导过程在上面写明了，但它尚未在一次完整的供应商评审中被用过。这一条与 [案例](../60-案例/README.md) 的缺口是同一个缺口。

## 六、评审会怎么开（半天）

**〔判断〕** 经验估计，单个供应商约 **3 小时**；一轮通常评 2–3 家。

| 时段 | 做什么 | 纪律 |
|---|---|---|
| 会前 | 自己答完 12 问**前提组**，把答案作为约束写进需求书；把本页发给供应商，**明确告知需要现场演示而非介绍** | 不提前发自己的前提组答案——否则会被复述回来 |
| 0:00–0:15 | 问 3.3 合规形态 | 不成立就结束，不要出于礼貌走完流程 |
| 0:15–1:45 | 逐条过 V1–V7、V9，**每条当场记 0/1/2** | 禁止「这个我们会后补充材料」拖过计分。会后补的材料按 1 分计，不按 2 分 |
| 1:45–2:15 | 问 2.2（讲一个失败的项目）与 5.1 的五条追问 | 这半小时的区分度通常高于前面 90 分钟 |
| 2:15–2:45 | 交付团队负责人答 V1–V6（若与售前不同人） | 这一项缺席，总分按 **×0.8** 计 |
| 2:45–3:00 | 当场算分、填结论、记下所有 0 分项 | **0 分项当天就转写成合同验收条件草稿**，否则会在商务阶段消失 |

## 七、读完之后明天做什么

1. **先答自己的六问**：用 [开工前 12 问](06-开工前12问.md) 的前提组（Q1–Q4、Q10、Q12）写出答案，作为需求书的约束条件。**这一步不做，下面全部无效。**
2. **把本页第三节发给候选供应商**，明确写「需要现场演示与文档页码，不接受功能列表」。
3. **把 3.3 的合规形态问题提前到第一通电话**，不要留到评审会。
4. **按第六节排一次 3 小时的评审**，并指定一个人负责当场计分——不指定就不会有人记。
5. 评审结束后，把所有 0 分项抄进合同验收条件草稿，再与 [投入产出测算](08-投入产出测算.md) 第五节的叫停条件合并，形成一份完整的立项附件。

> **如果你现在还没到选型阶段**：先做 [成熟度诊断](01-成熟度模型.md) 与 [决策清单工作坊](03-决策清单工作坊.md)。
> **在 M0 阶段做供应商评审是无效的**——你还不知道要买什么来解决哪个决策，任何方案都会显得合理。
