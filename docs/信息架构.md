## 顶层结构：两条平级主线

```
方法论总结（领域知识体系化）        实践（可执行工具）
        │                                │
        │  这个领域是怎么回事              │  明天做什么
        │  5 模块 30 主题                 │  10 套工具
        └────────────┬───────────────────┘
                     │
        行业剖面 · 研究 · 关于（支撑板块）
```

**关键设计决定**：方法论与实践**平级**，不做「理论 → 应用」的层级。
理由：实践的十套工具（成熟度诊断、120 天、工作坊、模板、反模式、12 问、合规与安全、
投入产出测算、自建 vs 采购与退出剧本、供应商评估清单）各自可独立交付，
不要求读者先读完方法论。这也让实践部分可以直接作为商务切入点。

## 设计原则

1. **每个模块标注主题数与阅读时长**——借鉴参考站 Learning Hub 的做法，降低进入门槛
2. **三种内容性质显式标注**〔共识〕〔争议〕〔判断〕——这是可信度的来源，也是与同类站最大的差异
3. **每页都有明确的下一步**——模块间有 上一篇/下一篇 导航，不留死胡同
4. **反面内容与正面内容同等可见**——反模式、失败症状、未解问题
5. **决策者 50 分钟能读完主线**——提供三条阅读路径

## 视觉方向

面向 CIO/CTO，因此：**冷静、克制、高信息密度**。

- 浅色底 + 深墨文字 + 单一强调色（深青 `#0d5c56`），深色模式跟随系统
- 系统中文字体栈，正文 17px，行高 1.78
- 大量表格与判据清单——这是「可执行」的视觉证据
- 三种内容性质用彩色小徽章区分：共识（青）/ 争议（砖红）/ 判断（灰）
- 不用插画、不用渐变、不用动效
