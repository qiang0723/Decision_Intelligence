1.1 问题空间：企业 AI 到底卡在哪

共识 企业 AI 的规模化率极低，且失败原因高度集中在非模型环节。这一条现在可以用具体数字支撑：

数字来源
88% 企业至少在一个职能用了 AI，但仅 7% 完全规模化；39% 有 EBIT 影响且多数 <5%McKinsey 2025-11，n=1,993
仅约 5% 达到可产生变革性影响的成熟度；60% 报告收益甚微或没有BCG 2025-09，n>1,250
42% 的公司放弃了多数 AI 计划（上年 17%）；平均报废 46% 的 PoCS&P Global 2025-03，n>1,000
原型到生产平均 8 个月；仅 48% 进入生产Gartner 2024-05
障碍分解：集成 46%、数据访问与质量 42%、变更管理 39%Anthropic + Material 2026
预测：到 2026 年缺乏 AI-ready 数据的项目将有 60% 被放弃；63% 的组织数据未就绪Gartner 2025-02，n=248。是预测不是实测

出处与方法论限定见 引用与数据来源。

两条必须交代的限定

利益披露：「障碍分解中模型能力不在首位」这条证据来自 Anthropic 的调研，而 Anthropic 售卖模型——这个结论对其有利，读者应据此打折。

曾经的错误：本站在 2026-08-23 之前写过「企业 AI 的失败率远高于消费级 AI 应用」。核实后发现，所有可查的研究都只测企业侧，没有任何一份用同一口径做过这个对比。该表述已删除。

三种主流的问题定义

不同流派对「卡在哪」的回答不同，这直接决定了他们的解法：

流派问题定义解法盲区
数据派数据没打通数据湖 / 湖仓 / 中台集中 ≠ 语义统一
知识派模型不懂企业知识RAG / 知识库 / 微调解决了「知道」，没解决「能做」
流程派流程没自动化RPA / 工作流 / Agent 编排自动化了动作，没自动化决策

判断 三种定义都对了一部分，但都不完整。真正的问题是：

企业没有一层机器可理解、且业务承认的语义骨架，因此 AI 既不知道这家企业是什么，也不知道能对它做什么。

数据派解决了「数据在哪」，知识派解决了「知道什么」，流程派解决了「怎么执行」。三者之间缺的那一层——这家企业由哪些东西构成、它们之间发生什么、能对它们做什么——就是本体。

一个有用的判别问题

「瓶颈不在模型」的准确版本

争议 这是本方法论最核心、也最容易被过度陈述的一条。诚实的表述必须是有条件的：

对于结构化、可验证、短时程的企业流程，边际瓶颈已从模型转移到集成、数据与组织。
但对于长时程、跨系统、要求高可靠性的自主决策，模型可靠性仍是硬约束。

反方证据必须列出，它们是有分量的：

  • METR 2026-01：视觉/计算机操作类任务的 50% 可靠度时程比软件任务低 40–100 倍；许多可靠性关键任务需要 98%+ 成功率才值得自动化。同时任务时程六年来每约 7 个月翻一番、2024–25 期间每约 4 个月翻一番——说明能力仍是在变动的那个变量
  • run-to-run 方差是模型属性，治理层消除不掉：pass^4 常比 pass^1 低 15–25 个百分点；90% 的基准分可能对应约 70% 的生产可靠性
  • 时间上的自我反驳：2025–26 年 agent 得以部署的前提条件恰恰是模型侧的（推理模型、更长上下文、工具协议、成本坍塌）。这条命题是对此刻的描述，不是一条规律。
判断

判断一个企业 AI 方案是否触及真问题，只需问一句：
这个系统被允许改变什么？

答不上来 → 它是知识派或数据派的方案，价值上限是「更快地看见」
答得上来 → 它必须面对权限、审批、可逆、审计——也就是真正困难的部分

1.2 四代企业数据架构的演进

2026-08-23 更正

判断 「数据架构分几代」不是领域共识（此前本站标〔共识〕，错）。本节的四代分期是本站自建的教学装置。

必须说清它与已有分期的关系：Dehghani（Data Mesh 原文）讲三代——私有企业数仓+BI → 大数据/湖生态 → 现代云平台；而她把 Data Mesh 定位为对第三代失败的回应，不是第三代本身。本站把 Data Mesh 当作自己的第三代、把 Hadoop 湖与云上湖仓合并进第二代——恰好在她划分二/三代的那条线上合并了。Gartner 另有一套分期，Inmon 与 Kimball 则是同时代的方法论之争而非代际关系。

第一代：报表时代（1980 年代末–2000 年代）

数据仓库 + BI 报表。特征：面向汇总，事后回顾。
时间锚点：Devlin & Murphy 架构论文 1988，Inmon《Building the Data Warehouse》1990/1992，Kimball《The Data Warehouse Toolkit》1996。
⚠️ 本站此前写「1990s–2000s」，晚了约十年，已更正。

第二代：大数据与湖时代（2006–2010 年代末）

Hadoop（2006）→ 数据湖（James Dixon 2010-10-14 提出该词）。特征：面向规模，先存后用。
⚠️ 湖仓（Lakehouse）不属于这一代，它是 2020（Databricks 2020-01-30 博文，CIDR 论文 2021-01）。本站此前把湖仓放进「2010s」，错了整整十年，已更正。

共识 这一代解决了存储与计算的规模问题，也留下了最大的遗产问题：数据沼泽——数据都在，但没人知道哪个能用。

第三代：语义与治理时代（2019–2023）

Data Mesh（首篇 2019-05，四原则 2020-12）、数据合同（2022-08 被推起来）、指标/语义层、MDM 复兴。特征：面向可信，谁负责数据。

⚠️ 两处更正：①「2018」没有任何锚点，已改为 2019；②语义层与 MDM 都不是这一代的发明——语义层可上溯至 1990 年代 Business Objects 的 universes 与 OLAP，MDM 是 2000 年代技术。这一代是它们的复兴与治理化。

⚠️ 关于 Data Mesh 有一处本站曾犯的稻草人化：说它「终点是把可信数据交给人」不准确——第四条原则联邦式计算化治理讲的正是把治理策略计算化地固化进平台。准确的差异表述是：Data Mesh 自动化的是治理，不是决策。

判断 方向是对的，但它止于数据供给。它让「数字是可信的」，没有让「决策是自动的」——它的终点仍然是把可信的数据交给人。

第四代：决策与行动时代（应拆成两条线）

⚠️ 本站此前笼统写「2023– 」，不准确。应拆开：本体 / 决策智能约 2021–22 起（Gartner 早在 2021-10 就把 Decision Intelligence 列为 2022 年十大战略技术趋势；Foundry Ontology 更早，是 2010 年代中期）；Agentic 2023– 起（ChatGPT 2022-11，Palantir AIP 2023-04）。

争议 这一代的边界还没有定论——放权到什么程度、责任如何分配、评测如何做，业界没有统一答案。

演进的一条主线

第一代  数据在哪      →  存取问题
第二代  数据有多少    →  规模问题
第三代  数据可不可信  →  治理问题
第四代  能不能自己动  →  授权问题   ← 当前所在

判断 每一代都没有取代上一代，而是叠加。2026 年社区调研（自选样本，非严格抽样）显示云数仓仍占主环境 44%、湖仓 27%、混合 12%——数仓从未消失。

一条被降级的主张

本站此前写「第四代的失败案例，绝大多数是因为跳过了第三代」。现降级为〔假设〕：没有任何研究测过这个因果。最接近的支持只是相关性（Gartner 的 AI-ready 数据数据）。而且有直接反证：MIT NANDA 报告把失败归因于学习/记忆/反馈缺失——"Tools fail not because of poor models, but because they don't learn, adapt, or integrate"——不是治理缺失。

保留它的理由是它可指导行动；但它不能作为论证的支点使用。

1.4 概念坐标系：这些词到底什么关系

共识 这个领域术语混乱，同一个词在不同语境下含义不同。先把坐标系立住。

按「解决什么问题」分类

概念解决的问题层次
数据湖 / 湖仓数据在哪、怎么存算基础设施
MDM 主数据名词的唯一与准确数据治理
数据合同 / Data Mesh谁负责数据、变更怎么管数据治理
语义层 / 指标平台数字是什么（口径唯一）语义
知识图谱关系是什么语义
本体 Ontology这家企业是什么，能对它做什么语义 + 行动
RAG / 向量库模型如何取到相关文本智能
Agent 框架多步任务如何编排智能
RPA / 工作流已确定的流程怎么执行行动
行动契约系统被允许改变什么、怎么改行动 + 治理

三组最容易混淆的概念

本体 vs 知识图谱

共识 技术实现上高度重叠，本体常用图结构承载。

判断 关键差异是行动：知识图谱通常只读、面向检索与推理；本体必须绑定可执行的行动并承载权限。不能触发状态变更的本体，只是图谱。

本体 vs 语义层 / 指标平台

共识 指标平台是本体的一个子集（管住指标口径唯一）。

判断 本体还要管对象、关系、生命周期状态机、行动与权限。没有行动的语义层是 BI 的延伸，不是决策平台。

Agent vs RPA

共识 RPA 自动化的是已确定的流程，Agent 处理的是需要判断的任务。

判断 真正的分界不是技术，是问题类型：RPA 不问「该不该做」，只问「怎么做」。企业 AI 的价值在前一个问题上。

2026-08-23 软化

本站此前写「右上角是唯一有持续价值的位置，其余象限的工具都会遇到价值天花板」。这个表述过强且无论证——大量企业从 BI 与数仓获得的是长期、稳定、可观的价值（2026 年云数仓仍占主环境 44%）。准确的说法是：其余象限的价值上限低于右上角，但不等于没有持续价值，也不等于应该被替换。

1.5 本方法论的适用边界

判断 明确说清不适用的地方，比多列适用场景更有价值。

适用

  • 决策高频、可逆、有明确 Owner、有现成落点系统的业务域
  • 已达 M1（数据已集中、有可用的 BI/报表）的组织；M0 组织请先补数据工程
  • 单 Agent 或确定性编排 + 模型节点的场景

不适用或覆盖不足

情形说明
低频、不可逆的战略决策是否进入新市场、是否收购——这是人的领域，本方法论不应被用于此
多 Agent 协作的审计模块五 5.3 承认这是未解问题。本方法论当前只覆盖单 Agent 场景
模型能力本身是约束的任务长程一致性、跨模态、需要 98%+ 可靠度的任务
组织政治导致的失败sponsor 变更、预算被砍、关键人离职（见 1.3）
托管大模型的严格可重放本方法论承诺「给定代码版本 + 数据版本可重放」，这对托管模型不成立——模型会被下线、涨价、变更行为。见 运行约束
