5.1 整合：决策智能架构 DIA

判断 本节是我个人的整合框架。前四个模块总结的是领域现状，这一节是我认为它们应该如何合成。

决策智能架构，是把企业的事实与企业的行动，通过一层业务承认的本体缝合起来，并在权限、证据、可逆四条约束下，交给分级授权的智能体去驱动的架构。

记忆锚点：一个中心，两个方向，四条约束。

D决策界面谁在决策 · 依据什么 · 谁担责
▲ 决策需求向下驱动
A行动可写回 · 可逆分级 · 审批链 · 幂等 · 频次上限
I智能规则 / 模型 / Agent · 工具即本体行动 · 分级自治
O本体★ 中心　对象 · 属性 · 关系 · 事件 · 指标 · 行动绑定
F事实口径权威唯一 · 血缘可追 · 时点正确
▲ 事实向上支撑
横切四约束 · 贯穿全部五层

权限　定义在本体上；Agent 继承调用者权限，无人值守时以担责岗位的委托身份运行。
证据　任何结论可追溯到输入与版本；坏消息不可隐藏；证据链自身也需被治理。
可逆　默认可撤销；R3 自动化需满足四条件，缺一即保留人闸。
运行　环境隔离 · 配额熔断 · 发布回滚 · 可观测。

为什么本体必须在中心

判断 一旦本体只是「一个可选的语义层」，就会立刻出现绕过它的捷径：报表直连数据库、Agent 写自由 SQL、前端硬编码业务公式。三个月后企业就有了第二套、第三套口径。

架构判据

除本体外，不存在第二条通往业务语义的路径。

5.2 在范式版图中的位置

范式关系关键差异
Palantir Foundry/AIP同一象限，思想来源借鉴其 semantic + kinetic 两分法内核（本站此前误写为「三层」，已更正）；不照搬重服务模式、全平台锁定、全企业本体优先
Data Mesh互补解决「谁负责数据」；止于数据供给，不涉及行动闭环
Lakehouse底座解决存储与计算，不解决语义
语义层 / 指标平台本体层的子集管指标口径；没有行动的语义层是 BI 的延伸
知识图谱技术手段之一面向检索推理、只读；本体必须可执行、承载权限
MDM 主数据前置能力MDM 是名词的正确性；本体是名词 + 动词 + 权限的完整性
RPA / 工作流行动层的实现手段RPA 自动化已确定的流程；本架构自动化决策本身
Agent 框架智能层的实现工具框架解决编排；Agent 的能力边界应由本体决定，而不是由框架能力决定

相对 Palantir 的补充

2026-08-23 更正：这一节的前提有两处错

此前的叙事是「Palantir 三层回答了『是什么』，我补上『怎么跑起来』」。

①不存在 semantic-kinetic-dynamic 三层，官方是两分法。
②「工程细节公开材料里基本没有」是错的——Palantir 文档逐条覆盖了参数校验、撤销回退、审批链（Ontology proposals，官方类比 Pull Request）、权限传播、幂等、时点正确、本体分支。

站得住的对照是：Palantir 把这些作为 Foundry 的产品特性文档化，而不是作为一套可迁移到任意技术栈的工程方法论。本框架试图提供的是后者。

在这个前提下，本框架相对公开材料补上的是：

补充解决什么
对象准入五判据本体膨胀
业务 Owner 制度本体腐化
行动十一要素契约让 kinetic 层能真正上生产
可逆性分级 + R3 四条件「敢不敢开权限」这个真问题
分级自治 L0–L4dynamic 层的放权依据
四条横切约束权限传播、证据链、失败关闭
组织承接人机权责 + 被取消的旧动作

Palantir 提供的是一个产品里的实现；本框架试图提供的是一套不绑定产品的工程纪律。
这个定位比此前的「它回答是什么、我回答怎么做」诚实，也更站得住。

5.3 未解问题与研究方向

一份不列出自己盲区的方法论总结，是不可信的。以下是我认为这个领域尚无好答案的问题。

已有明确分歧的问题　争议

#问题现状
①编排范式的边界在哪确定性工作流 vs 自主 Agent，两派都能举出成功与失败案例。目前没有可操作的判别标准，多数团队靠试错。我的暂定立场见 3.3
②生成式系统的评测方法论尚未成熟LLM-as-Judge 与人工判断的一致性因任务而异；离线评测与在线表现的相关性弱。目前没有一个企业敢说自己的评测体系是充分的
③本体的构建应该多自动化用 LLM 从数据库 schema 自动生成本体的尝试很多，但生成的是「数据模型的镜像」，不是业务语义。自动化与「业务承认」之间的矛盾没有解决

缺少数据的问题

#问题为什么重要
④本体的「复利」从第几个场景开始显现？增量派的核心论据是复用，但复用率随场景数增长的曲线形态没有公开数据。这是我最想研究的一个问题
⑤M1 → M2 的真实成本口径裁决权的组织分配需要多长时间、多高层级推动，没有基准。国内企业起点普遍低于欧美，成本差异有多大也不清楚
⑥弃权率的合理区间过低说明系统不知道自己不知道，过高说明没有价值。中间区间在哪里、取决于什么，没有答案

我认为会成为焦点的问题

#问题说明
⑦责任分配的法律与制度形态「担责者永远是人」目前是一条工程原则，但自动执行规模扩大后，它需要制度化支撑（岗位定义、保险、审计标准）。目前完全空白
⑧组织记忆的表达形式「这个供应商经常延迟」应沉淀为本体属性还是留在记忆库？前者可审计但笨重，后者灵活但不可查。权衡未有共识
⑨多 Agent 系统的审计单 Agent 的证据链已清楚。多 Agent 协作时「谁做的决定」变得难以回答。企业级多体审计方法基本没有

总结全文的三句话

  1. 企业 AI 的瓶颈不是模型是企业没有一层机器可理解、且业务承认的语义骨架。
  2. 只读的智能存在价值上限价值发生在写回，而写回的门槛是治理，不是技术。
  3. 自主不是能力描述，是授权描述放权的依据是可逆性与证据，不是准确率与信心。
